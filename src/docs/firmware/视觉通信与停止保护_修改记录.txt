一、修改文件与作用
------------------------------------------------------------
1. Task/Inc/Auto_aim.h、Task/Src/Auto_aim.c
   - 移除任务循环主动调用 USB 接收回调、重复读取旧缓冲区的路径。
   - 仅根据真实接收字节处理完整消息；保留跨回调的部分数据。
   - 首字节、CRC、模式范围及浮点有限性检查通过后才更新内部快照。
   - 无效数据不会刷新有效接收时间，并触发保护锁定。
   - 未完成消息也有期限，不允许无限等待的部分数据维持有效通信。
   - 消费者通过 Auto_aim_GetCommand() 获取短临界区内复制的一致快照。
   - 快照读取自身检查是否过期，不依赖接收任务恰好先执行超时检查。
   - 失败读取返回无效标志并清零输出快照。

2. Src/usbd_cdc_if.c
   - 真正的接收回调传入本次实际长度。
   - USB 初始化/反初始化会清除旧状态并锁定视觉控制。
   - USB 未配置或类数据不存在时，发送函数返回失败，避免直接解引用空指针。
   - 视觉任务调用发送函数时保护检查与使用的窗口，避免反初始化并发破坏类数据。

3. Task/Src/ModeControl.c
   - 使用有效快照判断视觉许可。
   - 非开火视觉状态转为 Stop，不再依赖原来遗漏的 AUTO Prepare1 分支。
   - 非法拨杆值不会继续保留上一轮模式。
   - 只在观察到两个拨杆都位于下挡时，尝试确认保护锁定解除。

4. Task/Src/Shoot.c
   - AUTO 的 Prepare1 及其他未处理状态显式进入停止输出路径。
   - 撤销视觉开火或失联时，采用现有停止 PID 将各路速度目标设为 0。
   - 发送之前再次核对停止条件，避免仅依赖较早更新的 ShootMode。
   - 直接核对停止拨杆，减少等待模式任务更新造成的窗口。
   - 同一轮重复安全检查不会重复积分停止 PID。
   - 这里的“停止输出”不意味着电流必为 0：实际 PID 可能输出制动电流。

5. Task/Src/GimbolControl.c
   - 不再直接读取未经保护的接收结构体。
   - AUTO 通信失效时调用已有 Gimbol_Stop()，不走原来的目标丢失后扫描路径。
   - 本轮使用视觉命令时，在发送前再次核对通信保护状态。
   - 持续通信中“没有目标”的既有处理和真正的通信失效分开。

二、新增的保护锁定行为：需要交接给操作人员
------------------------------------------------------------
上电、USB 初始化/反初始化、通信过期、无效消息都会锁定视觉控制。
重新收到数据不能单独解除锁定。

解除锁定需要同时成立：
  - 固件观察到 s[0]、s[1] 都为下挡（软件停止位置）。
  - 已收到新鲜、完整、校验通过的 mode 0 中立消息。
  - 没有尚未处理完的部分消息。

mode 1/2/3 不用于解除锁定。旧消息也不用于解除锁定。
两个拨杆对应的实际物理开关仍须由电控核对；不能只依赖注释推断。
若上位机一直发送非中立消息，保护会保持锁定，这是本次明确的安全行为。

保护的作用范围
  - AUTO 失联/锁定：云台采用既有停止处理，发射端采用既有零速度停止处理。
  - RC 模式下的视觉控制许可被撤销后，云台仍可能按原有遥控逻辑动作。
  - RC 模式、发射拨杆上挡的独立手动发射路径未改为依赖视觉通信。
  - 因此本保护不等于整机断能，更不能替代独立停止装置或遥控失联保护。
  - 即使是有效的 mode 0，也不代表 AUTO 云台必须静止；它和通信失效不同。

三、超时设置
------------------------------------------------------------
宏：VISION_SAFETY_TIMEOUT_MS，定义在 Task/Inc/Auto_aim.h。
当前暂定默认值为 50 ms，可在构建宏中覆盖。

这只是本次保护实现的待验证界限，不是已测得的可靠时序参数。
不能用标称发送频率推导“绝不会误触发”。
实际停止延迟还包括任务调度、输出通信和机械响应。
电控需要记录并验证该值是否满足设备的安全响应要求。

四、故障可观察状态
------------------------------------------------------------
调试器可查看 VisionSafety：
  inhibited：当前是否锁定。
  accepted：通过接收有效性检查的消息计数。
  rejected：无效输入/过期部分消息等拒绝事件计数。
  expired：已接收命令过期事件计数。
  disconnected：初始化/反初始化等显式清除连接状态的事件计数。

计数供诊断，不是新增的通信协议字段；独立读取多个计数不保证同一时刻快照。
